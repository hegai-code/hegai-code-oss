# Hegai Signer (macOS)

Приложение в строке меню, которым владелец подписывает релизы внешнего агента Hegai Code
по Touch ID, без Терминала. Заменяет `deploy/release-signer/offline-sign.mjs`, проверки те же.
MacBook вне флота: приложение ходит только на публичные адреса `https://code.example.com`.

## Установка

1. Скачать https://code.example.com/dl/signer/HegaiSigner-mac.zip, распаковать.
2. Перенести `HegaiSigner.app` в «Программы» и открыть (подписано Developer ID, нотаризовано).
3. По желанию в окне включить «Запускать при входе».

## Первый запуск

В окне нажать «Создать ключ». Появится строка публичного ключа: «Скопировать» и отправить в чат,
её добавят в `deploy/release-keys.txt`. Ключ вшивается во внешние сборки, поэтому сборку делают
после добавления строки.

## Как подписывается релиз

Раз в 15 минут (и при запуске, и по «Проверить сейчас») приложение спрашивает
`GET /api/release-signing/pending`. Новый неподписанный релиз: уведомление «Релиз X ждёт подписи»,
точка в значке меню. В окне видны версия, коммит, sha256 (сверить с тем, что напечатала сборка),
дата. «Подписать (Touch ID)»:

1. скачивает сборку только с `https://code.example.com/…` (без редиректов, не более 32 МБ);
2. требует `sha256` == заявленному, маркер `HEGAI_AGENT_EDITION=external` (и не `internal`),
   версию в сборке == заявленной;
3. запрашивает Touch ID (или пароль Mac), подписывает манифест
   `hegai-code-agent-release/1\nedition=external\nversion=…\nsha256=…\n`;
4. проверяет подпись своим публичным ключом и отправляет `POST /api/release-signing/signature`.

## Где ключ

Ключ Secure Enclave лежит в связке ключей защиты данных (data-protection keychain) в группе
`AZWU5VAA73.net.hegai.signer`: использовать его могут только бинарники, подписанные нашей командой
с этим entitlement (профиль Developer ID встроен в приложение). Доступ только по Touch ID
текущих отпечатков (`biometryCurrentSet`), без пароля. Добавили, удалили или сбросили отпечатки,
потеряли Touch ID: ключ недоступен, нужен новый («Новый ключ…») и заново добавить его в доверенные.

`~/Library/Application Support/HegaiSigner/` (папка 0700, файлы 0600):

- `se-key.bin` — идентификатор ключа Secure Enclave в связке ключей;
- `wrapped.json` — Ed25519-seed, обёрнутый ключом Secure Enclave (ECDH P256 + HKDF-SHA256 + AES-GCM);
- `pubkey.txt` — публичный ключ, формат строки как в `deploy/release-keys.txt`.

Seed в открытом виде появляется в памяти только на время подписи. Если есть любой из файлов ключа,
приложение не создаёт новый поверх (неполный набор — «восстановите или сделайте Новый ключ»).
«Новый ключ…» после подтверждения переносит файлы в `backup-<дата>/`. Ротация: новую строку добавить
в `release-keys.txt`, релиз подписать старым ключом, дальше новым.

## Проверка скачанного приложения

```bash
codesign -dv --verbose=4 /Applications/HegaiSigner.app 2>&1 | grep TeamIdentifier=AZWU5VAA73
spctl -a -vv /Applications/HegaiSigner.app     # source=Notarized Developer ID
```

## Что приложение доказывает, а что нет

Версия, sha256, коммит и адрес сборки приходят с хаба. Приложение гарантирует лишь одно: вы подписываете
ровно ту сборку, которую оно скачало (sha256 совпал, редакция external, версия совпала). Оно НЕ доказывает,
что хаб не скомпрометирован. Сверяйте версию и sha256 с тем, что Claude сообщил в чате, и подписывайте
только при совпадении.

## Потеря Mac

Секрет без этого Mac не восстановить (Secure Enclave не экспортируется), но пока Mac у чужого,
ему нужен ещё Touch ID/пароль. Действия: убрать строку ключа из `deploy/release-keys.txt`
(после того как агенты получили релиз, подписанный новым ключом), создать ключ на новом Mac.

## Сборка

На Mac с Xcode: `swift test`, затем `./build.sh` (нужен профиль `~/signer.provisionprofile`: `swift tools/asc-profile.swift <файл>`) (Developer ID, нотаризация, zip, выгрузка на хаб).
