## Что установлено по исходникам

- В цепочке `html → body → #root → .app → .body → .main-col → .main`
  нет `padding-top: var(--sat)`. В сессии верхний inset принадлежит `.ws-head`.
  Правило `.main > *` снимается более специфичным селектором для `.workspace`.
  Оснований вычитать или прибавлять 54px к высоте приложения не найдено.
- `WorkingLine` находится внутри `.log-inner`, а не под композером.
  Класс `idle` зависит от фокуса, черновика и вложений, а не от `busy`.
  Соседний `.composer-foot` скрывается тем же мобильным правилом во время хода.
- `useComposerHeight` публикует высоту на `.chat`; переменная используется для
  плавающих кнопок, не для размеров или отступов цепочки контейнеров.
- На мобильном экране сессии `.topbar` скрыт через `display: none`.
  Его `backdrop-filter` не может объяснить клип на этом экране. На других
  экранах, где бар видим, это остаётся возможной причиной.
- Сдвиг, радиус и тень `.body` заданы одним селектором в одном блоке
  `@media (max-width: 860px)` (без `pointer: coarse` в текущем файле).
  Работающий сдвиг исключает несовпадение этого селектора как объяснение
  отсутствующего радиуса. Непрозрачный фон потомка сам по себе не должен
  обходить округлый `overflow: hidden` предка; для этого нужен сбой клипа.
- Старая фикстура копирует разметку композера без его хуков. Кроме того, она
  не подключала `fonts.css`, а её viewport meta отличался от продукта.
  Эти расхождения устранены для дальнейшего исследования; они не объявляются
  доказанной причиной полосы.

## Изменения

`sessionBusyInset` монтирует настоящий `SessionWorkspace` с настоящим `Chat`,
активным ходом, пустым черновиком и часами около `1:04`. Подменяются ответы RPC,
а не DOM композера. Добавлены светлый и тёмный кадры 390×844, sat=54, sab=34.

Снималка теперь сохраняет JSON геометрии рядом с PNG. В нём есть layout/visual
viewport, границы всех контейнеров, padding, footer display, transform, radius,
clip, shadow и `--composer-h`. `scripts/layout-probe.mjs` содержит самостоятельную
функцию `measureLayout`: для вызова в консоли Safari нужно скопировать её без
`export` и выполнить `JSON.stringify(measureLayout(), null, 2)`.

Для открытого ящика добавлен `clip-path: inset(0 round var(--radius-device))`
на внутренний `.main-col`. Это явная граница клипа потомков, включая отдельные
композитные слои. Тень оставлена на внешнем `.body`, чтобы clip-path не отрезал
её вместе с содержимым. Это кандидат на исправление WebKit, не подтверждение
конкретной причины на iPhone. Новых цветов, радиусов или отступов нет.

## Проверки и ограничения

Прошли `npx tsc -p web/tsconfig.json --noEmit`, `npm run build --workspace web`,
существующие `type-scale.test.ts` и `shell-invariants.test.ts`, проверка синтаксиса
двух `.mjs` и `git diff --check`.

Запуск указанной пользователем команды снималки завершился ошибкой Chrome:
`setsockopt: Operation not permitted`. Отдельный Vite также получил
`listen EPERM ::1:5198`. Headless shell через pipe, без HTTP и WebSocket,
завершился на `sandbox_host_linux.cc: shutdown: Operation not permitted`.
Политика этой сессии запрещает повышение разрешений. Поэтому нет ни замеров
реального браузера, ни новых PNG; имеющиеся `.shots` не выдаются за результаты.

В среде с работающим браузером:

```sh
CHROME_PATH=/root/.cache/puppeteer/chrome/linux-144.0.7559.96/chrome-linux64/chrome npm run shot --workspace web sessionBusyInset
CHROME_PATH=/root/.cache/puppeteer/chrome/linux-144.0.7559.96/chrome-linux64/chrome npm run shot --workspace web sessionInset
CHROME_PATH=/root/.cache/puppeteer/chrome/linux-144.0.7559.96/chrome-linux64/chrome npm run shot --workspace web drawerInset
```

Сравнение JSON должно сначала показать, заканчивается ли `.app` у нижней
границы viewport, затем где заканчиваются `.workspace`, `.chat`, `.composer`
и `.composer-box`. При закрытой клавиатуре и sab=34 ожидаемый padding снизу
композера по CSS равен 24px. Если все контейнеры доходят до низа, но на iPhone
остается полоса, нужны его visual viewport, scroll offset и версия загруженного
CSS — подмена safe-area переменных не воспроизводит эти состояния WebKit.

Для скругления проверить на устройстве ящик поверх сессии и поверх страницы
с видимой `.topbar`, обе темы, прокрутку содержимого и закрытие ящика.
Снимок Chromium способен проверить обычную геометрию и сохранность тени,
но не доказать исправление композитинга iOS.

Коммитов и деплоя нет. `server/src/cli/fleet-skills.ts` не изменялся этой работой.
