# tgbot — Hegai Code в Telegram

Ещё один клиент хаба, рядом с `web/` и `ios/`. Он **не меняет протокол**: всё,
что он делает, уже умеет `/ui` (`shared/src/web-protocol.ts`). Поэтому в
`shared/`, `server-rs/` и `agent/` ради него не тронуто ни строки.

Что умеет: выбрать машину → проект → сессию, создать сессию с категорией,
вести переписку, отвечать на вопросы агента кнопками, принимать голосовые и
скриншоты, присылать уведомление, когда что-то ждёт ответа.

## Главное решение: в чате только речь

Поток хода несёт шесть видов событий. В чат попадает **один** — `assistant`.
`tool_use`, `system`, `status` — машинерия; `partial` — те же слова по буквам;
`result` — граница хода. Пока агент работает, единственный сигнал — «печатает…»
самого Telegram, а когда ход кончился, кнопки появляются **на последнем
сообщении агента**, а не отдельным сообщением. Включить машинерию можно в
`/settings` → «Показывать инструменты».

Саджесты — по желанию, двумя способами: на экране запуска кнопка «Подсказки»
разворачивает готовые первые ходы под выбранную категорию, а в настройках
«Предлагать саджесты» включает `enrich_request` — до трёх быстрых ответов
кнопками после хода.

## Кто может пользоваться

Белый список Telegram id (`CC_REMOTE_TG_ALLOW`). Все разрешённые аккаунты ходят
в хаб **под одной личностью** — как если бы делили один браузер. Это осознанное
ограничение первой версии.

Чтобы открыть бота сообществу, привязки «этот Telegram = этот пользователь
хаба» не хватит одного бота: у хаба нет учётки для сервисов, каждая личность —
человек с opaque-сессией (`server-rs/src/main.rs`, `authenticated_user`).
Правильная форма — новый класс учётных данных рядом с `device_credentials`,
плюс режим `?native=tg` в SSO, который после логина возвращает человека в
`t.me/<bot>?start=<код>`. Пока этого нет, белый список — единственная честная
граница.

### Узнать свой Telegram id

```bash
TELEGRAM_BOT_TOKEN=… npx tsx tgbot/src/cli/tg-id.ts
# напиши боту любое сообщение — утилита напечатает CC_REMOTE_TG_ALLOW=<id>
```

Сервис бота при этом должен быть остановлен: Telegram пускает только один
`getUpdates` на токен, второй получает 409.

## Переменные окружения

| Переменная | Обязательна | Смысл |
|---|---|---|
| `TELEGRAM_BOT_TOKEN` | да | токен от @BotFather |
| `CC_REMOTE_TG_ALLOW` | да | Telegram id через запятую |
| `CC_REMOTE_HUB_HTTP` | нет | база хаба, по умолчанию `http://127.0.0.1:4318` |
| `CC_REMOTE_TG_STATE` | нет | файл состояния, по умолчанию `~/.cc-remote-tgbot.json` |
| `CC_REMOTE_TG_SESSION` | одно из двух | готовая сессия (значение куки `__Host-cc-remote-auth`, на http-хабе `cc-remote-auth`) |
| `CC_REMOTE_SSO_SECRET` + `CC_REMOTE_TG_HUB_USER_ID` + `CC_REMOTE_TG_HUB_EMAIL` | одно из двух | минтить сессию самому (только на хаб-боксе) |

Сессия сама продлевает себе срок при использовании, так что живой бот не
протухает. Если хаб её отверг, бот перевыпускает её — при условии, что у него
есть SSO-секрет.

## Запуск и проверка

```bash
npm run build --workspace shared && npm run build --workspace tgbot
npm test --workspace tgbot            # рендер: экранирование, разбиение, чистка шума

# локально против прод-хаба
TELEGRAM_BOT_TOKEN=… CC_REMOTE_TG_ALLOW=… CC_REMOTE_HUB_HTTP=https://code.example.com \
CC_REMOTE_TG_SESSION=… npx tsx tgbot/src/index.ts

# сквозной смоук: настоящий хаб, настоящий Telegram, синтетические нажатия
CC_REMOTE_TG_STATE=/tmp/tgbot-smoke.json npx tsx tgbot/src/cli/tg-smoke.ts [machine]
CC_TG_SMOKE_RUN=1 …                   # ещё и заводит живую сессию, тратит токены
```

Смоук пишет в реальный чат — это и есть способ увидеть, как выглядит рендер.

## Новые заявки в Hegai Code

Раз в минуту бот спрашивает хаб `GET /api/admin/access?state=waitlist` и про
каждого нового человека в листе ожидания пишет всем из `CC_REMOTE_TG_ALLOW`
сообщение с кнопкой «Активировать». Кнопка зовёт ту же
`POST /api/admin/access/activate`, что вкладка «Доступ» в вебе, поэтому в
аудите стоит владелец бота. Ключ шлюза активация не выдаёт (см.
`after_activate_hooks` в `server-rs/src/access_api.rs`). Дописанная позже
заметка «что хочу построить» обновляет сообщение; кого активировали в вебе —
у того кнопка гаснет. При первом запуске уже ждущие записываются молча, без
рассылки. Если бот ходит в хаб не админом (403), функция выключается сама.
Память — поле `waitlist` в `state.json`, код — `src/waitlist.ts`.

## Деплой

```bash
ssh rental-app            # hub-vps-01, тот же бокс, что и хаб
bash /home/cc-remote-src/deploy/deploy-tgbot.sh
```

Первый запуск ставит юнит и просит создать `secrets.conf` (см.
`deploy/cc-remote-tgbot.service`). Бот работает **из чекаута**, а не из
скопированных артефактов: Node резолвит `@cc-remote/shared` через симлинк
воркспейса.

## Чего он намеренно не делает

- Не открывает сессию, которую держит редактор, — предлагает перехват
  (`takeover`), единственный санкционированный путь.
- Не показывает историю с телом инструментов: `session.messages` зовётся с
  `toolChars: 0`, потому что 95–99% байтов транскрипта — дампы файлов.
- Не шлёт `compact`: сообщение объявлено в схеме, но хаб его не диспатчит.
